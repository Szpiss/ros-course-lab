# 山地-城市融合多机器人仿真答辩介绍稿

各位老师好，我这个课程大作业最开始是一个山地小车 Gazebo 仿真项目，场景里有山地地形、山路、岩石障碍物和终点红旗，小车可以在 Gazebo 中生成出来，并通过 `/cmd_vel` 做地面运动控制。

在这个基础上，我继续把项目扩展成了一个“山地 + 城市 + 空中无人机”的综合仿真环境。现在启动最终 launch 后，Gazebo 里不只是单独的山地，而是在同一个 world 中同时包含山地场景和城市街景。城市部分有主路、支路、十字路口、人行道、不同高度的建筑、路灯、树木、路牌和简单障碍物，并且有一条道路把山地区域和城市区域连接起来，所以它不是两个割裂的场景，而是融合在一起的综合场景。

整个系统通过 ROS launch 管理启动。`mountain_city_air_demo.launch` 会启动 Gazebo，加载综合 world，生成原来的山地小车，并启动无人机巡航节点。场景和模型主要用 Gazebo world、SDF 和 URDF/Xacro 来组织：山地和城市属于 Gazebo world/SDF 场景，小车继续使用原来的 Xacro/URDF 模型，无人机是一个轻量的 SDF 四旋翼模型。

地面小车负责展示地面机器人在山地和城市道路环境中的运动。它保留了原来的 `/cmd_vel` 控制方式，所以既可以自动演示，也可以用键盘 WASD 手动控制。空中的无人机没有接入复杂飞控，而是通过一个 ROS Python 节点调用 Gazebo 的 `/gazebo/set_model_state` 服务，让无人机按固定高度和椭圆轨迹在山地与城市上空巡航。

我选择这种简化飞行控制方式，是因为课程项目更重视稳定展示和系统集成。如果直接引入 PX4、MAVROS 或复杂空气动力学模型，依赖会比较重，也容易在答辩机器上启动失败。现在这种方式虽然不是完整真实飞控，但优点是可控、稳定、直观，而且很容易解释清楚：ROS 节点负责计算飞行轨迹，Gazebo 负责显示模型状态变化。

这个项目的重点不是单一模型，而是多场景、多模型、多运动对象的综合仿真。通过这个项目可以看到 ROS 和 Gazebo 在机器人建模、场景搭建、仿真启动管理、多机器人协同展示方面的基本应用。最终效果就是：地面有山地和城市融合场景，小车在道路上运动，空中无人机持续巡航，整体比普通单机器人实验更适合做课程大作业展示。
